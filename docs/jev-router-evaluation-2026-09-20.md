# Jev 라우터 개선·검증 — 2026-09-20

## 결과와 범위

SwitchGPT 내부 모델/effort 라우터의 로컬 후보를 개선했다. 설치된 앱, 계정 인증, 사용자 Codex 설정은 교체하지 않았다. 커밋·푸시·배포는 하지 않았다.

Codex 요청의 모델과 effort가 기본값이다. 신뢰할 수 있는 분류만 여섯 조합으로 변경한다. 불확실한 응답·지원하지 않는 요청·API 오류는 원문을 유지한다. 모델 사용 비율을 인위적으로 맞추지 않는다.

| 조합 | 작업 기준 |
| --- | --- |
| Luna medium | 방법이 정해진 번역·요약·사실 조회·계산·문구 변경·도구/이미지 작업 |
| Luna max | 요구사항이 정해져 있고 로직·예외 처리·테스트를 구현해야 하는 작업 |
| Sol medium | 원인 조사·설정 확인·자료 비교·해결 방법 선택 |
| Sol high | 경쟁 상태·간헐적 실패·교착·데이터 보존 등 어려운 국소 분석 |
| Astra medium | 경계·계약·요구사항·장애 처리를 함께 정하는 아키텍처 |
| Astra high | 여러 시스템·지역의 정합성·복구·상충 요구사항을 함께 해결하는 설계 |

반복 단계나 출력 길이만으로 effort를 높이던 기준을 제거했다. 명시적 모델/오케스트레이터 선택, 목표를 알 수 없는 요청, 삭제·발행·운영 배포·전송·접근 변경 실행은 KEEP 분류 지침으로 보존한다. 이 분류 정책은 권한 검사나 실행 안전장치를 대체하지 않는다.

## 신뢰도 해석

공식 문서의 `confidence`는 후보 확률 분포의 집중도다. 개별 분류의 정답 확률이나 실제 작업 성공률이 아니다. 기존 기준 `confidence >= 0.8`은 유지했다. 임계값을 낮춰 전환률을 높이지 않았다. 후보별 확률도 평가 자료에 보존한다.

응답은 허용된 라벨·유한한 0~1 확률·확률 합·선택값과 최대 확률의 일관성을 검사한다. API의 반올림을 고려해 합에는 0.04 오차를 허용한다. 모순되거나 잘못된 응답은 원문 유지다.

근거: [TypeSafe Choice](https://docs.typesafe.ai/primitives/choice.md), [confidence 정의](https://docs.typesafe.ai/confidence.md), [Jev 1.13 기준 중복 주의사항](https://docs.typesafe.ai/model-jaggedness/jev-1.13.md). 7개 선택지에는 단일 Choice를 유지했고, 추가 왕복이 필요한 계층형 호출을 도입하지 않았다.

## 실제 요청 100건 비교 — 개발 표본

같은 48개 스레드에서 추출·비식별화한 100건을 재사용했다. 이 표본을 보고 분류 기준을 조정했으므로 독립 정확도 자료가 아니다. 이 대화의 이전 반복 결과와 비교한다.

| 항목 | 이전 v2 | 수정 v3 |
| --- | ---: | ---: |
| 실제 Jev HTTP 200 | 100/100 | 100/100 |
| 모델 또는 effort 변경 | 28 | 35 |
| Luna medium | 0 | 17 |
| Luna max | 13 | 0 |
| Sol medium | 15 | 18 |
| 중앙 지연 | 534.5ms | 545.5ms |
| p95 지연 | 610ms | 625ms |
| 입력 토큰 | 110,049 | 106,649 |

v2의 Luna max 13건은 정해진 이미지 생성 작업이었다. v3에서 medium으로 분리했다. 이 표본에 한정된 구현·고난도 설계가 부족하므로 Luna max/Sol high/Astra가 선택되지 않은 것을 품질 결함으로 단정하지 않는다.

사전 위험 플래그의 삭제 관련 9건과 명시적 스킬 관련 5건은 변경하지 않았다. 맥락 부족 플래그 21건 중 4건은 전환됐다. 플랫폼/오류가 생략된 로그인·배포 조사, 발행 스크립트화에 관한 질문, 명시된 문서 검토다. 알려진 조사 목표와 빠진 증거를 구분한 결과지만, 실제 첨부 내용과 후속 답변 품질은 검증하지 않았다.

## 별도 사전 라벨링 60건 — 독립 합성 평가

기존 프롬프트/결과를 읽지 않은 평가자가 새 표본을 작성했다. API 호출 전에 root가 모호한 다섯 사례의 허용 조합을 검토하고 라벨·기준을 고정했다. 결과를 본 뒤 라벨이나 프롬프트를 수정하지 않았다. 여러 언어·명시적 보존·파괴적 요청·인용문·지시 주입·문맥 경계를 포함했다. 실제 코드/로그를 첨부하지 않은 사례는 요청 의도와 명시된 범위만 평가한다.

사전 통과 기준은 KEEP 위반 0건, 승인된 분류의 허용 라벨 일치율 90% 이상, 전환 가능한 표본의 승인율 50% 이상이었다.

| 측정 | 결과 |
| --- | ---: |
| HTTP 200 | 60/60 |
| 분류 승인 | 38건 |
| 승인 중 허용 조합 일치 | 37/38 = 97.4% |
| 전환 가능한 표본 승인율 | 38/46 = 82.6% |
| KEEP 대상 원래 설정 유지 | 14/14 |
| 전환 가능하지만 판단 보류 | 8건 |
| 실제 모델/effort 변경 | 31건 |
| 중앙 / p95 / 최대 지연 | 532.5 / 720 / 1,210ms |
| 입력 / 출력 토큰 | 60,972 / 4,507 |

승인 분포: Luna medium 11, Luna max 8, Sol medium 4, Sol high 5, Astra medium 7, Astra high 3. 승인 7건은 이미 같은 조합이어서 요청을 변경하지 않았다.

불일치 1건(H018)은 시간·비용 가중치로 통근안을 계산하고 추천하는 사례다. 사전 라벨은 Sol medium인데 Luna medium이 선택됐다. 결과를 본 뒤 정답 라벨을 바꾸지 않았다. 주입 문구를 포함한 인용문 H056은 Luna medium 후보였지만 낮은 신뢰도로 유지됐다. 경계 작업의 보류를 숨기지 않고 적용 범위와 분리했다.

이는 소규모 합성 분류 평가다. 97.4%를 일반 사용자 요청의 정확도, 모델 간 우열, 작업 성공률 또는 비용 절감률로 해석할 수 없다. 각 모델로 실제 작업을 수행시키는 대조 실험과 설치 앱의 upstream 실사용 검증은 하지 않았다.

## 구현 및 회귀 검증

- 동일 턴 재사용, 스레드 격리, single-flight, 설정 generation 무효화, bounded TTL/캐시 유지.
- 최신 메시지뿐 아니라 직전 문맥도 캐시 키에 포함. 같은 ‘진행해’가 다른 문맥의 결과를 재사용하는 결함 수정.
- 텍스트와 파일/알 수 없는 content가 섞인 요청은 외부 분류를 생략. 이미지·음성·긴 입력·지원하지 않는 형식도 원문 유지.
- 인식 가능한 사용자 문장의 키·비밀번호는 외부 전송 전 차단. 실제 값에 `password` 등이 포함돼 placeholder로 통과하던 결함 수정. 제한된 형식 검사이며 일반 DLP는 아니다.
- API 오류/2초 timeout/잘못된 응답은 원문 유지. 2초 timeout은 URLSession의 협력적 취소를 전제로 한다.
- 변경 모델이 명시적으로 거절됐고 응답을 아직 전달하지 않았을 때만 원문으로 한 번 재시도. 다음 도구 요청도 원래 조합 유지. 정상 스트리밍은 재실행하지 않음.
- Swift 테스트 **84개 통과**. 실제 Jev 호출은 이번 개선 단계 **100+60=160건**, 실제 모델 작업 실행은 없음.
- 최종 코드로 저장된 160개 Jev 응답을 오프라인 재생: 모델/effort 결정 모두 동일. 실제 표본 9번은 `choice=keep`인데 Luna 확률이 더 높아, 강화된 검사에서 이유만 `low_confidence` → `malformed_response`로 변경. 원문 유지에는 차이 없음.
- 읽기 전용 리뷰의 P2 3건 수정·재검토 완료. 로컬 앱 빌드/ad-hoc 서명 완료, `git diff --check` 통과.
- Graphify 로컬 코드 그래프 갱신. 기존 ModelRoutingTests.swift 132행 parser 경고는 남아 있으나 Swift 전체 테스트는 통과. 유료 semantic label 갱신은 실행하지 않음.
- 이번 개선은 화면 변경 없음. 앞선 격리 UI 검증 이후 설치 앱 교체/실행 계정 변경은 하지 않음.
