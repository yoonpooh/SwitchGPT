# Effort 최적화와 실제 저장소 작업 검증 — 2026-09-20

## 결과

로컬 라우터 후보를 개선했다. 작은 구현에 불필요하게 Luna max를 지정하던 기준을 줄였고, 복잡한 상태 처리뿐 아니라 어려운 순수 알고리즘도 max 대상으로 유지했다. 명시적 파일 보존 요청은 원래 모델을 유지하도록 로컬 검사도 추가했다.

**구현과 회귀 검증은 완료했지만, 모든 실제 작업에서 더 빠르거나 더 정확하다는 결론은 아니다.** 실제 작업에서 발견한 지시 준수 실패와 시간 초과를 아래에 그대로 기록한다. 설치 앱 교체·배포·커밋·푸시는 하지 않았다. 기본 모델/effort는 여전히 Codex가 보낸 값이며, confidence 기준 0.8도 유지했다.

## 적용한 기준

| 작업 | 선택 |
| --- | --- |
| 번역·요약·정해진 도구 작업, 작은 관례적 파싱·검증·정렬·설정·재시도 구현 | Luna medium |
| 여러 상태·순서·만료·취소 제약이 상호작용하는 구현, 복잡한 파서·계산기하·수치 알고리즘 | Luna max |
| 일반 조사 / 어려운 원인 분석 | Sol medium / high |

| 명시적 모델 선택·목표 불명·위험 실행·엄격한 파일 보존 | 원래 설정 유지 |

테스트가 필요하거나 파일 수가 많다는 이유만으로 max를 선택하지 않는다. max를 상태 관리에만 한정하면 어려운 순수 알고리즘을 놓친다는 리뷰 의견을 반영했다.

`RoutingInputPolicy`는 최신/직전 사용자 문장의 명확한 기존 테스트·보호 파일 수정 금지 표현을 인식하면 Jev 호출 전에 원문을 유지한다. 일반적인 ‘이 함수만 변경’ 범위 지정과 인용된 정책은 구별하고, 따옴표로 감싼 실제 파일명은 유지한다. 명시적 문구의 제한된 패턴 검사이며 모든 자연어 표현을 인식하지는 않는다. 시스템/개발자 지시를 외부 분류에 보내거나 실행 모델의 파일 권한을 바꾸지 않는다. 이미 고정된 동일 턴의 도구 후속 요청도 뒤집지 않는다.

**KEEP은 전환을 하지 않는 조치다. 원래 모델이 Luna이면 그대로 Luna이며, 파일 보존 준수 자체를 보장하지 않는다.**

## 분류 평가

별도 평가자가 기존 프롬프트/결과를 읽지 않고 30건을 작성했고, root가 호출 전에 라벨과 모호한 문구를 검토했다. 최초 후보는 승인 21건 모두 사전 허용 라벨과 일치했다. 리뷰에서 순수 알고리즘 경계를 보완한 뒤 기존 30건과 새 4건을 재검증했다: 승인 24/24 일치, KEEP 6/6 유지, 복잡한 명세 구현 6/6 max. 수정에 참고한 기존 작은 구현 4건도 medium으로 분류됐다.

실제 저장소 평가에서 파일 보존 문제가 드러나 해당 기준을 추가했다. 자연어 KEEP 지침만으로는 정확한 실행 프롬프트 4건이 계속 변경되는 실패가 발생했다. 이 결과를 숨기지 않고 로컬 검사로 보강했다.

최종 41건은 기존 34건 + 실제 실행과 동일한 전체 요청 4건 + 일반 범위/보호 파일/인용 정책 3건이다. 이 자료는 **실패를 반영한 보정 후 회귀 평가**이며 새 독립 holdout 성공률이 아니다.

| 최종 엔진에서 저장 응답 재생 | 결과 |
| --- | ---: |
| 사례 | 41 |
| 승인된 분류의 허용 라벨 일치 | 25/25 |
| KEEP 대상 유지 | 11/11 |
| 로컬 파일 보존 검사로 Jev 생략 | 5 |

원시 Jev 호출 결과와 최종 로컬 검사 재생 결과는 별도 파일로 남겼다. 최종 41건을 새로 전부 API 재호출했다고 주장하지 않는다. 이번 최적화 단계의 실제 Jev 호출은 개발 4 + 최초 30 + 수정 34 + 저장소 4 + 보존 회귀 41 = 113회다.

## 실제 저장소 작업

표준 라이브러리만 사용하는 작은 Python 저장소 4개를 독립적으로 만들었다. 각 저장소는 소스·별도 호출자·문서·공개 테스트를 포함한다. 모든 seed가 외부 검증에서 실패하고, 별도 reference는 통과하는 것을 작성자와 리뷰어가 각각 확인했다.

모델은 실제로 파일을 탐색하고 수정한 뒤 테스트를 실행했다. 답변에 코드를 적는 것만으로 평가하지 않았다. 각 복제 작업 폴더 밖의 grader로 최종 결과를 확인했다. grader는 프롬프트에 제공하지 않았지만 OS 차원의 읽기 차단은 없으므로 ‘접근 불가능한 숨김 테스트’는 아니다. 명령 기록에서 grader/reference 접근은 관찰되지 않았다. 일부 Luna 실행은 전역 지침에 따라 저장소 밖의 Graphify 스킬을 읽었으므로 완전한 저장소 읽기 격리도 아니다.

| 작업 | Astra medium | 후보가 선택한 조합 | 후보 시간 | 기능 검사 | 원래 엄격한 gate |
| --- | ---: | --- | ---: | --- | --- |
| 설정값 정규화·우선순위 | 52.8초 | Luna medium | 73.4초 | 통과 | 실패: 기존 테스트 파일에 테스트 추가 |
| CSV 가져오기·검증 | 71.9초 | Luna medium | 97.8초 | 통과 | 실패: 기존 테스트 파일에 테스트 추가 |
| TTL/LRU·복사 격리 | 70.3초 | Luna max | 157.9초 | 통과 | 통과 |
| 순서·중복·스트림 이벤트 처리 | 80.1초 | Luna max | 240초 제한 | 통과 | 실패: 종료 응답 전 시간 초과 |

Astra medium 4건은 기능 검사·파일 보존·종료를 모두 통과했다. 후보의 기능 검사는 4/4지만, 최초 엄격한 gate는 1/4였다. 테스트 추가는 기존 검사를 삭제하거나 약화한 것이 아니었으나 명시된 금지 조건 위반이므로 통과 처리하지 않았다. 시간 초과 실행도 디스크상의 구현이 통과했을 뿐 작업 완료로 세지 않았다.

이전 정책과 비교하기 위해 작은 두 작업을 Luna max로도 실행했다. 설정은 151.0초에 완료했지만 같은 테스트 파일 보존 위반이 있었다. CSV는 기능 검사는 통과했으나 240초 제한에 걸렸다. 작은 작업을 medium으로 내리면 이전 max보다 빨라진 사례는 있었지만 **Astra medium보다 빨라진 것은 아니었다**.

‘기존 파일에 추가도 금지, 새 테스트 파일만 생성’이라는 구체적인 조건으로 설정 작업을 두 모델에 다시 실행한 탐색적 확인에서는 Astra 52.6초, Luna medium 62.9초로 모두 엄격한 gate를 통과했다. 이 두 재검사는 최초 실패를 지우거나 독립 재현 성공률을 높이는 데 사용하지 않았다.

총 실제 모델 실행은 원 비교 10회와 조건 명확화 확인 2회다. 12개 결과의 외부 기능 검사와 별도 공개 테스트 재실행은 모두 통과했다. 실행 로그에서 각 모델의 실제 로컬 테스트 성공도 확인했다. 실패한 테스트 기대값을 스스로 수정하고 다시 통과한 사례도 기록에 남겼다.

### 분류 입력과 실행 입력의 정합성 수정

최초 저장소 비교는 짧은 task만 분류기에 넣고, 실행 때 테스트 파일 보존 조건을 덧붙였다. 따라서 최초 비교는 선택 모델의 작업 능력을 보여주지만 완전히 동일한 요청의 라우팅 검증은 아니었다.

최종 검증에는 이 조건까지 포함한 **실제 실행과 동일한 전체 프롬프트**를 사용했다. 네 요청은 모두 로컬 보호 검사로 원래 Astra medium을 유지한다. 해당 모델·effort·프롬프트의 실제 실행 결과는 이미 원 비교에서 4/4 통과했으므로 이를 연결해 확인했다. 모델 작업을 새로 네 번 실행했다고 주장하지 않는다. 원래 선택 모델이 다르면 이 결과를 그대로 일반화할 수 없다.

따라서 최초 엄격한 gate 실패는 여전히 사실이며, 최종 후보는 발견된 제약 요청에서 모델 전환을 피하는 방식으로 대응한다. 무조건 Luna로 낮추거나 max로 올려 문제를 숨기지 않았다.

## 검증과 제한

- Swift 자동화 테스트 87개 통과. 보호 문구·인용문·따옴표 파일명·기준 모델이 Luna인 경우에도 원문 유지·외부 호출 생략을 포함한다.
- 기존 캐시·동시 요청·설정 무효화·도구 후속 요청·upstream 원문 재시도 검증 유지.
- 독립 리뷰의 순수 알고리즘 누락, grader의 불필요한 딕셔너리 순서 조건, 인용 파일명 감지 누락 수정. 최종 리뷰에 남은 차단 이슈 없음.
- 로컬 앱 빌드/ad-hoc 서명과 diff 검사 통과. 화면 변경이 없어 UI를 다시 실행하지 않았다. 설치 앱은 그대로다.
- Graphify의 기존 로컬 코드 갱신 모드 사용. 기존 Swift parser 경고와 semantic 이름 갱신 안내는 남아 있으며 유료 label 갱신은 하지 않았다.
- 원 비교는 최대 동시 실행 2개였으나 일부 시간에는 별도 조건 확인 2개가 겹쳤다. 지연은 단회·공유 환경·스킬/캐시 영향을 포함하므로 정밀한 속도 벤치마크가 아니다.
- 범용 최적성, 구독 사용 한도 절감, 비용 절감, 장시간 브라우저/다중 저장소 작업 품질은 입증하지 않았다. 원래 모델을 유지하는 동작을 파일 권한 또는 정답 보장으로 해석하면 안 된다.
