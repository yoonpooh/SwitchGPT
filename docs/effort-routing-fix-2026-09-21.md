# effort 라우팅 보완

## 확인한 문제와 수정

독립 모델/effort 분류 뒤에도 과거 6개 결합 preset이 지원 목록으로 남아 있었다. 이 때문에 Luna high, Sol max, Astra max는 confidence가 충분해도 적용되지 않았다. 기본값 low 역시 순위에 없어서 medium/high/max로 올릴 수 없었다.

로컬 Codex 0.155.0의 `models_cache.json`(fetched_at: 2026-09-20T18:03:34Z)에서 세 모델 모두 low/medium/high/max를 지원함을 확인했다. 캐시의 계정 identity나 인증정보는 복사하지 않았다.

- 자동 선택 후보 medium/high/max를 세 모델 모두에 허용한다.
- low를 알려진 입력 기준값으로 처리해 상향과 모델만 변경할 때의 low 보존을 지원한다.
- xhigh/ultra와 생략된 effort는 계속 임의로 재작성하지 않는다.
- 모델 변경과 effort 하향 임계값 0.8, 전역 KEEP, 명시적 선택 보존, upstream 거부 시 원본 재시도는 유지한다.

이 수정은 실제 차단 경로를 재현한 결과다. 앞서 관찰한 다섯 질문의 medium 유지 원인이 모두 이 제한이었다는 뜻은 아니다. 기존 로그에는 당시 제안·confidence가 없으므로 소급 판정할 수 없다.

## 진단 로그

`relay-events.jsonl`의 `modelRouting.diagnostics`에 모델/effort별 제안, confidence, 설정 활성 여부, 적용 임계값과 결과 사유를 기록한다. 원문 질문, 키, 인증 헤더, 원시 분류 응답은 추가하지 않는다. 과거 로그는 diagnostics 없이 계속 읽을 수 있다.

원본과 같음, 꺼짐, confidence 미달, 지원하지 않는 기준/조합, 전역 KEEP, 적용, upstream 거부를 구분한다. 후속 요청은 원래 분류 진단을 재사용하고 upstream 거부 후에는 실제 거부된 차원을 표시한다.
