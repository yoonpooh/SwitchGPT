# 실제 모델 실행 비교 — 2026-09-20

## 결론

분류 결과만 비교하던 이전 평가에서 한 단계 더 나아가 실제 Codex 모델을 호출하고, 반환한 구현은 별도 프로세스에서 실행했다. 이번 표본에서 라우팅에 따른 정답·기능 저하는 없었다. 그러나 **속도 최적화 효과는 확인하지 못했고, 특히 한정된 구현을 일괄 Luna max로 보내는 기준은 과할 가능성이 드러났다.**

라우터 정책·설치 앱·사용자 설정은 변경하지 않았다. 커밋·푸시·배포 없음.

## 방법

- 비교 기준은 실험상 Astra medium으로 고정. 앱 기본값은 여전히 Codex가 보낸 모델/effort다.
- 실제 소스의 `IntelligentModelRouter`와 Jev를 사용해 새 작업을 분류한 뒤, 선택된 모델/effort로 Codex CLI를 호출했다.
- `--ignore-user-config --ephemeral --sandbox read-only`, 임시 작업 디렉터리 사용. 사용자 모델 설정을 저장하지 않았다.
- 모델에는 도구 호출·파일 접근·브라우징·위임을 금지하고 문제에 필요한 자료만 제공했다. 실제 이벤트에서도 도구 호출 0건이었다.
- 변경된 조합은 같은 입력으로 기준 모델과 각각 실행. 같은 조합을 유지한 작업은 한 번 실행한 결과를 공유했으며 독립적인 비교 쌍으로 세지 않았다.
- 실행 순서는 사례마다 교대, 최대 동시 실행 2개, 각 호출 제한 180초. 각 모델/사례는 한 번 실행했으므로 지연의 통계적 유의성을 주장하지 않는다.
- 코드는 네트워크·파일 쓰기·사용자 홈 읽기를 막은 별도 `sandbox-exec` 프로세스에서 테스트했다. 재시도 예외 객체 동일성, 구간 병합과 입력 불변성, 윤년·ASCII 형식·날짜 경계, 마지막 항목 유지 및 객체 동일성을 검사했다.
- 작업의 정답과 테스트 요구사항은 결과 검사 전에 고정. 구현 세부 채점 코드는 모델에 제공하지 않았다.

## 호출과 품질

초기 16개 + 후속 2개 문제에서 Jev 18회 호출. 초기 문구 치환 1개는 마침표가 입력에 포함되는지 모호해서 제외하고, 명시적 구분자를 넣은 새 문제로 대체했다. 두 모델이 똑같이 마침표를 보존했으므로 모델 실패로 세지 않는다. 보충 1개는 Sol medium의 일반 비교 작업을 검증하기 위해 추가했다.

| 항목 | 결과 |
| --- | ---: |
| 유효한 서로 다른 작업 | 17 |
| 독립적으로 두 모델을 실행한 비교 쌍 | 12 |
| 원래 조합을 유지해 결과를 공유한 작업 | 5 |
| 주 비교의 유효한 출력 | 29/29 통과 |
| 기준은 통과했으나 라우팅 모델은 실패한 사례 | 0/12 |
| 생성 코드의 행동 검사 | 모델별 1,335개 통과 |
| 탐색적 Luna medium 추가 실행 | 4/4 통과 |
| 모델 호출 수 | 본 비교 31 + effort 추가 4 + 준비 확인 1 |

유효 표본: 계산·CSV 정규화·문구 치환·문서 사실 추출, 재시도 함수·구간 병합·날짜 검증·안정적 중복 제거, 설정 우선순위·SQL·경쟁 상태·오래된 응답 분석, 오프라인 동기화·분산 원장·시스템 이전의 설계 제약, 모델 보존, 백업 방식 비교.

Luna medium/max, Sol medium/high, Astra medium/high가 실행됐다. Astra medium은 기준 모델과 보류 결과로 실행됐다.

## 지연 — 주 비교

각 행은 해당 작업들의 호출 지연 중앙값이다. Codex 프로세스 시작, 제공자 응답, 기존 스킬 문맥 등을 포함한다. 오른쪽 열에는 별도로 측정한 Jev 지연을 더했다.

| 선택 조합 | 비교 쌍 | Astra medium | 선택 모델만 | 선택 모델 + Jev |
| --- | ---: | ---: | ---: | ---: |
| Luna medium | 4 | 6.52초 | 6.93초 | 7.48초 |
| Luna max | 4 | 10.50초 | 15.75초 | 16.35초 |
| Sol medium | 1 | 6.24초 | 5.29초 | 5.75초 |
| Sol high | 1 | 5.98초 | 4.69초 | 6.17초 |
| Astra high | 2 | 7.50초 | 7.87초 | 8.39초 |

12개 비교 쌍의 요청별 시간 합계는 기준 96.22초, 선택 모델만 115.43초, Jev를 더하면 122.94초였다. 마지막 값은 약 28% 길다. 병렬 실행 전체의 실제 벽시계 시간이 아니라 요청별 지연의 합계다. 캐시 hit, CLI 기본 문맥, 모델별 tokenization, 서버 부하의 영향을 통제한 순수 모델 속도 벤치마크가 아니다.

## Luna effort 추가 확인

주 비교에서 Luna max로 간 구현 4건 모두 기준보다 느렸다. 같은 프롬프트·테스트를 Luna medium으로 추가 실행했다. 결과는 모두 통과했고 1,335개 행동 검사도 동일하게 통과했다.

| 사례 | Astra medium | Luna max | Luna medium 추가 실행 |
| --- | ---: | ---: | ---: |
| 재시도 함수 | 9.21초 | 19.36초 | 19.14초 |
| 구간 병합 | 11.79초 | 13.28초 | 10.43초 |
| 날짜 검증 | 13.42초 | 18.23초 | 13.27초 |

| 중앙값 | 10.50초 | 15.75초 | 11.85초 |

이 네 사례에서는 max가 정확도 이점을 보이지 않았다. medium 추가 실행은 결과를 본 뒤 설계한 탐색적 비교이며, 나중 실행의 캐시 이점도 있을 수 있다. ‘Luna max가 항상 불필요하다’는 결론은 아니다. 다만 작은 표준 알고리즘 구현까지 무조건 max로 올릴 근거는 약해졌다.

## 판단과 한계

- **검증됨:** 이번 닫힌 입력 작업에서 정답과 코드 동작을 유지했다. 응답을 생성한 것만으로 통과 처리하지 않고 실제 코드를 실행했다.
- **개선 후보:** 단순하고 범위가 작은 구현의 Luna medium 허용 범위를 늘리고, max는 더 복잡한 예외·상태 추론이 필요한 구현에 사용하도록 후속 독립 평가가 필요하다. 이번 요청은 테스트이므로 라우터 기준은 그대로 뒀다.
- **미검증:** 실제 저장소 탐색→여러 파일 수정→도구 실패 복구, 브라우저·이미지 작업의 완료 품질, 긴 스레드의 문맥 유지, 설치 앱의 전체 실사용 경로. 설계 문제도 선택지가 주어진 좁은 불변식 검증이어서 실제 개방형 아키텍처 난이도를 대변하지 않는다.
- **미입증:** 일반 요청의 100% 성공률, 사용 한도 절감, 요금 절감, 모델별 평균 속도 우열. 구독 모델의 과금·한도 변환을 이 토큰 수로 계산하지 않았다.
